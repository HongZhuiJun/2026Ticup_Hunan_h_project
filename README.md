## 1. 系统组成

```text
┌──────────────────┐   UART2  115200 8N1   ┌─────────────────────┐   UART2  115200   ┌──────────────────┐
│  K230D + GC2093  │  13 B 定长帧 / 20 Hz  │  STM32F103C8T6      │  绝对角度命令      │  X42S 闭环步进    │
│  YOLOv8n INT8    │ ────────────────────▶ │  位置闭环 + 菜单     │ ─────────────────▶ │  + 曲柄连杆       │
│  NPU 本地推理     │                       │  72 MHz / 64 KB     │                    │  内置编码器       │
└──────────────────┘                       └─────────┬───────────┘                    └────────┬─────────┘
         ▲                                          │ 软件 I2C / GPIO                              │
         │ 摄像头俯拍摆杆                             ▼                                              ▼
         │                                  ┌──────────────────┐                        ┌──────────────────┐
         └──────────────────────────────────│ OLED 128×64 菜单  │                        │ 25 cm PPR 摆杆    │
              视觉闭环（20 Hz）                │ 3 个按键          │                        │ Φ1 cm 钢球        │
                                            └──────────────────┘                        └──────────────────┘
```

| 部件 | 型号 / 规格 | 作用 |
| --- | --- | --- |
| 主控 | STM32F103C8T6（LQFP48，HSE 8 MHz × PLL9 = 72 MHz） | 位置闭环、任务调度、菜单、串口 |
| 视觉 | 正点原子 K230D + GC2093 摄像头 | 钢球检测，输出像素 X |
| 执行 | ZDT X42S 闭环步进（内置编码器，串口给绝对角度） | 经曲柄连杆改变摆杆倾角 |
| 摆杆 | 25 cm 4 分 PPR 水管改造，凹槽 + 0.1 cm 刻度 | 钢球滚动轨道 |
| 钢球 | Φ1 cm | 被控对象 |
| 显示 | 0.96" OLED 128×64（软件 I2C） | 任务菜单与实时数据 |
| 按键 | 3 个（上移 / 确认 / 下移，低电平有效） | 菜单操作 |
| 调试 | ST-Link + SWD，OpenOCD | 下载与调试 |

### 接线（以代码为准）

| 信号 | 引脚 | 说明 |
| --- | --- | --- |
| K230 TX → STM32 RX | PA10（USART1_RX） | 115200 8N1，DMA1_Channel5 + IDLE 空闲中断 |
| STM32 TX → K230 RX | PA9（USART1_TX） | 预留，当前只收不发 |
| X42S | PA2 / PA3（USART2） | 串口命令 + DMA 发送 |
| OLED | PB6（SCL）/ PB7（SDA） | 软件 I2C |
| 按键 | PA4 / PA5 / PA6 | 上拉输入，按下为低 |
| 调试 | PA13 / PA14 | SWDIO / SWCLK |

> K230 侧 UART2 使用 GPIO44（TX）/ GPIO45（RX），与庐山派等板型不同，换板时需确认引脚定义。

## 2. 能做什么

OLED 三级菜单里可以选择 5 个任务，每个任务一套独立参数：

| # | 任务 | 目标与判据 |
| --- | --- | --- |
| 1 | 定点稳定 | O → +6 cm → −6 cm，各稳定 3 s；误差 ≤1.2 cm 且球速 ≤2 cm/s |
| 2 | 折返运动 | +6 cm → 立即折返 −6 cm → 回 0 cm 停止；到位误差 ≤1.2 cm |
| 3 | 连续跟踪 | 目标 = 8 cm × sin(2πt / 4 s)，参考位置 / 速度 / 加速度同相位解析给出 |
| 4 | 抗干扰 | 目标恒为 0，外力推走后自动拉回并重新稳定 |
| 5 | 任意位置 | 菜单设定 −10 ~ +10 cm，步长 1 cm |

视觉链路还做了失效处理：**未检测到钢球时 K230 发 −1**，STM32 立即停用旧位置、摆杆回平并复位 PID；超过 200 ms 没有合法帧判为视觉离线，不会拿上一帧数据继续闭环。

## 3. 软件架构

```text
hilab_assessment/
├── application/                 # 应用层：赛题任务
│   └── ball_control.c/h         #   5 个任务、参考轨迹、任务参数表、菜单注册
├── bsp/                         # 板级支持：只碰寄存器/HAL，不含业务
│   ├── delay.c/h
│   ├── gpio/gpio_key.c/h        #   按键读取
│   ├── gpio/gpio_oled.c/h       #   OLED 软 I2C 引脚
│   └── usart/usart1_k230.c/h    #   USART1 + DMA + IDLE 不定长接收
├── modules/                     # 通用模块：可复用、与赛题无关
│   ├── k230_to_stm32.c/h        #   视觉帧解析、物理位置换算、在线判定
│   ├── pid.c/h                  #   通用 PID（限幅、抗饱和、微分先行）
│   ├── oled.c/h / oled_data.c   #   显示驱动与字库
│   ├── oled_menu.c/h            #   三级菜单框架（只负责显示与按键）
│   ├── key.c/h                  #   按键消抖与事件
│   └── x_v2.c/h                 #   X42S 闭环步进串口驱动（第三方库）
├── vision/
│   └── main_zdyz_k230.py        # K230 / CanMV 端：YOLOv8n 检测 + LCD 预览 + UART2 发送
├── Core/                        # CubeMX 生成：时钟、DMA、GPIO、USART、中断
├── 电控C_Cpp开发规范_v0.1.md      # 本项目的分层、命名、注释、错误处理约定
├── 管球平衡控制系统_设计报告.md    # 方案论证、建模、测试与误差分析
├── hilab_assessment.ioc         # CubeMX 工程
├── Makefile                     # arm-none-eabi-gcc 构建
└── openocd_stlink.cfg           # ST-Link + SWD 下载配置
```

**分层原则**：`application` 只写赛题逻辑，`modules` 保证可复用，`bsp` 是唯一直接操作 USART/DMA/GPIO 的地方；菜单模块只负责显示与按键，不知道"任务"是什么，由 `ball_control` 在初始化时把 5 个任务函数注册进去。

数据流：`DMA 收字节 → IDLE 切帧 → 状态机解析 13 字节 → 像素转厘米 → 一阶滤波 + 差分测速 → 参考轨迹 → PID + 前馈 → 倾角限幅 → X42S 绝对角度 → 曲柄连杆`。

## 4. 通信协议（K230 → STM32）

固定 13 字节，大端序，115200 8N1，发送频率约 20 Hz：

| 字节 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- |
| 0–3 | 帧头 | — | 固定 `AA 55 01 08` |
| 4–5 | `current_x` | int16 | 钢球当前像素 X；**−1 表示未检测到** |
| 6–7 | `target_x` | int16 | 目标像素 X，当前固定 318（对应 0 cm） |
| 8–9 | `reserved_1` | uint16 | 保留，固定 0，当前不校验 |
| 10–11 | `reserved_2` | uint16 | 保留，固定 0，当前不校验 |
| 12 | `checksum` | uint8 | 前 12 字节逐字节异或 |

设计要点：

- 定长帧比 JSON / 字符串省带宽、好解析，也方便用逻辑分析仪直接看；
- 逐字节状态机切帧，帧头失配可自动重同步，字节流里出现 `AA AA 55 01 08` 也不会漏帧；
- 校验失败整帧丢弃；越界坐标（<0 或 >640）判为误检直接丢弃，不做"限幅猜位置"；
- 200 ms 无合法帧 → `K230ToStm32IsOnline()` 返回 0，控制进入安全态。

## 5. 控制算法

钢球在倾斜管内纯滚动，联立平动与转动方程：

```text
mg·sinθ − f = m·a
f·r = I·(a/r)，实心球 I = (2/5)m·r²
⇒ a = (5/7)·g·sinθ
```

取 g = 980 cm/s²，角度换成度：`a = 12.22·θ`，反解得加速度前馈系数 **θ = 0.082·a**（单位 ° 每 cm/s²）。质量与半径都被约掉，球的加速度只由倾角决定；输入倾角、输出位置，中间两次积分，是典型的双积分对象。

控制律：

```text
θ = Kp·e + Ki·∫e dt + Kd·(−ẋ) + Gv·ṙ + Ga·r̈
```

- 前馈不是可选：以 ±8 cm / 4 s 正弦跟踪为例，球到波峰时位置误差为 0，但仍需要 19.74 cm/s² 的反向加速度（≈1.62° 倾角）才能折回；纯反馈在误差为 0 时输出也是 0，结构上就跟不住。
- 微分作用加在测量值而不是误差上，避免目标从 +6 cm 跳到 −6 cm 时的微分冲击；
- 积分项单独限幅 + 抗积分饱和，输出整体限幅 **±3.5°**（再大摆杆会滑出底座投影）；
- 控制周期不写死：用前后两帧时间戳算 `dt`，并限幅在 20–100 ms，帧率波动时积分与微分的时间尺度仍然正确；
- 视觉中断优先级高于电机发送：帧延迟会让时间戳失真，而电机命令晚几十微秒没有影响。

任务 3 调试时可以通过 USART3（PB10）每帧打印一行数据，便于用串口示波器看跟踪曲线。

## 6. 视觉与标定

K230 端（`vision/main_zdyz_k230.py`）：

- YOLOv8n 单类别检测，模型输入 320×320，经 nncase INT8 量化后由 NPU 推理，实测约 20 Hz；
- 只保留 Y 条带 **215–266** 内的检测框（把检测限制在凹槽内），取最高分目标，置信度阈值 **0.15**，NMS 0.45；
- 未检测到发 −1；
- 摄像头通道 0 送 640×480 ST7701 LCD 做实时预览，通道 2 取 320×320 送推理；
- 通过 UART2（GPIO44/45，115200）发 13 字节帧。

标定（2026-09-28 重新实测）：广角镜头桶形畸变明显，画面中心约 33–34 像素/cm，两端压缩到 21–25 像素/cm，**相差 62%**。用单段直线拟合必然一端准、另一端偏差到厘米级，因此把钢球依次放在每厘米刻度上记录像素坐标，建立 **22 点标定表**，测量时用相邻两点线性插值。

结果：全量程分辨率优于 **0.5 mm**（中心约 0.29 mm，两端 0.4–0.48 mm），满足赛题 2 mm 的显示要求。标定表在 `modules/k230_to_stm32.c` 中，K230 侧与 STM32 侧必须逐项一致且随厘米单调递增，否则插值会回跳。

## 7. 编译、烧录与运行

### 7.1 固件（STM32）

工具链：`arm-none-eabi-gcc` + Make（CubeMX 生成，`TARGET = hilab_assessment`）。

```bash
make -j            # 生成 build/hilab_assessment.elf / .hex / .bin
make clean
```

烧录（ST-Link + SWD）：

```bash
openocd -f openocd_stlink.cfg \
        -c "program build/hilab_assessment.elf verify reset exit"
```

也可以用 STM32CubeProgrammer 直接下载 `build/hilab_assessment.hex`。工程可用 STM32CubeMX 打开 `hilab_assessment.ioc` 重新生成外设初始化代码（重新生成前注意保留 `USER CODE` 区块）。

### 7.2 视觉（K230）

1. 把训练并量化好的模型拷到 K230 的 `/sdcard/`，文件名与脚本里的 `KMODEL_PATH` 一致（默认 `steel_ball_yolov8n_320_v2_best.kmodel`）；
2. 用 CanMV IDE 打开 `vision/main_zdyz_k230.py` 运行；
3. 确认 UART2 的 TX/RX 与 STM32 的 PA10/PA9 交叉连接、共地。

### 7.3 上电流程

1. 装置放平，**手动把摆杆调平**，作为电机零点（当前零点依赖上电位置，每次上电都要做）；
2. 先给 K230 上电，确认 LCD 上能看到检测框；
3. 给 STM32 上电，OLED 显示主菜单，用 3 个按键选择任务；
4. 进入任务后观察球位与球速，异常时按返回键退出（摆杆回平）。

## 8. 实测结果

| 项目 | 要求 | 实测 |
| --- | --- | --- |
| 定点稳定误差（0 / ±3 / ±6 / ±9 cm） | ≤10 mm | 最大 5.8 mm（±9 cm 处），±6 cm 处最好 2.4 mm |
| 折返运动全程 | ≤5 s | 4.8 s |
| 折返三点最大位置误差 | ≤1 cm | 0.6 cm |
| 抗干扰回复时间 / 最终误差 | ≤5 s / ≤5 mm | 3.2 s / 4.2 mm |
| 位置显示分辨率 | ≤2 mm | 0.1 mm（显示两位小数） |
| 视觉测量分辨率 | ≤2 mm | 中心 0.29 mm，全量程 <0.5 mm |
| 视觉帧率 | — | 约 20 Hz |
| 连续跟踪动态误差 | ≤1.5 cm | 约 2 cm（**未达标**） |

连续跟踪没达标的原因：跟踪频率 1.57 rad/s 已接近闭环带宽，20 Hz 视觉 + 位置滤波带来约 50 ms 滞后，纯反馈压不下去，需要更准的前馈模型或延迟补偿。这是第二版之后仍待改进的点。

## 9. 与第一版相比，具体做了什么

- **分层重构**：把现场版混在一起的逻辑拆成 `application / bsp / modules`，菜单、PID、协议、步进驱动各自独立，换硬件只改 `bsp`；
- **参数表化**：5 个任务各一套参数（PID、限幅、参考轨迹），进入任务时整组加载，调一个任务不影响其他任务；
- **协议模块化**：13 字节帧解析、在线判定、像素—厘米换算收进 `k230_to_stm32`，附完整模块文档（含常见错误排查表）；
- **重新标定**：逐厘米重测 22 点标定表，替换现场版的临时数据；
- **失效处理**：−1 丢失、200 ms 离线、越界丢弃、退出任务复位，全部走同一条安全路径；
- **文档补齐**：《电控 C/C++ 开发规范》《管球平衡控制系统设计报告》和本 README。

## 10. 已知问题与后续改进

| 问题 | 现状 | 计划 |
| --- | --- | --- |
| 连续跟踪误差约 2 cm | 前馈模型精度有限 + 视觉滞后 | 速度一步预测补偿；前馈增益与微分系数解耦整定 |
| 电机零点依赖上电位置 | 每次上电手动调平 | 加零点开关或上电自动回零流程 |
| 左右机械比例不一致 | 现场用单一比例换算 | 拆成左右两个参数分别标定 |
| 管壁微小凹陷造成静摩擦死区 | 小误差时球被卡住 | 换内壁更平整的管；加死区补偿 |
| 视觉标定依赖人工逐点测量 | 22 点、约 10 分钟 | 做半自动标定工装，减少人为误差 |
